# OpenMontage

A Python tool library, a Remotion composer and a large body of instructions. The agent is the orchestrator: it reads `AGENT_GUIDE.md`, picks one of the pipeline manifests in `pipeline_defs/`, reads a stage director skill before each stage and calls the tools. At the pinned commit, `195eab2`, there are 13 manifests (12 productions plus `framework-smoke`) and the tool registry loads 151 tools in 26 capability groups. The X post that named it on 2026-10-30 repeats the README's "700+ agent skill and production-knowledge files" (`README.md:382`); the checkout holds 1,585 files under `.agents`, `.claude` and `skills/`, so the claim holds in its own unit, and 140 of those files are SKILL.md files.

Licences, read from the texts and not a legal opinion. Upstream's own code is GNU AGPL-3.0 (`LICENSE:1`): running it for our own productions is fine, while copying its code into this repository, or offering a modified copy to anyone over a network without publishing that modified source, is not. The renderer the zero-key path uses is Remotion, under its own licence: its packages say "SEE LICENSE IN LICENSE.md" (`remotion-composer/node_modules/remotion/package.json:23`) and upstream warns that "Companies may need to obtain a license for commercial use" (`.agents/skills/remotion/SKILL.md:146`). Remotion's pricing page, read on 2026-10-31 at remotion.dev/docs/license/pricing, makes it free with unlimited commercial use "for individuals and companies of up to 3 people", "terms apply", and otherwise requires a Company License, which bills automation at $0.01 a render with a $100 monthly minimum. Tee ruled on 2026-10-31, on a card, that his operation takes the free licence: "Free licence, 3 or fewer". The ruling rests on the pricing page; the full terms behind "terms apply" were not read, and the card said so. Stock assets, Piper voices and model weights carry their own terms; each stock source records a licence per asset (`tools/video/stock_sources/base.py`).

## Install

```bash
bash .claude/skills/openmontage/scripts/install.sh
```

Run it with a Bash timeout of at least 600000 ms, or in the background. A fresh install took 111 s on 2026-10-30 and 75 s with warm caches on 2026-10-31, and the Bash tool stops a command at 120 s by default.

It checks its prerequisites first (git, make, python3, npm, npx, and uv or a python3.11; the refusal names `OPENMONTAGE_PYTHON` for a machine that has another Python), warns when ffmpeg is missing or Node is older than 22, which HyperFrames needs, and prints the node, uv and ffmpeg versions it found. It then fetches exactly commit `195eab24478dc9363326aec437aefc3701635ddf` into `$OPENMONTAGE_HOME` (default `~/OpenMontage`) and runs upstream's `make setup` with Python 3.11, the version upstream's CI runs. Before that call it clears `VIRTUAL_ENV`, `CONDA_PREFIX` and `VENV_DIR`, because upstream's Makefile otherwise installs into the caller's active environment, and it caps the fetch and `make setup` each at `OPENMONTAGE_SETUP_TIMEOUT` seconds (900 by default). The output also goes to `openmontage-setup.log` in the checkout. It then loads the tool registry and prints the counts.

Exit codes: 0 installed; 3 refused before anything changed; 4 installed with an optional step skipped, which the summary names; any other code is the failing tool's own (git 128, make 2, the time limit 124). It refuses a target inside this repository, a directory that is not a git checkout, a checkout whose origin is not OpenMontage, a checkout at another commit, and a checkout at the pin with local changes to tracked files, because `make setup` would then run edited code. It resumes its own interrupted fetch and reuses a clean checkout at the pin. `test_openmontage_installer.py` runs every one of those paths offline.

`~` is the ephemeral container home, so the install is gone when the container is reclaimed and each new session runs the installer again. Anything worth keeping from `projects/` goes to Drive before the session ends.

**What the install runs, and what it can reach.** It executes third-party code. Python packages are pinned to `scripts/constraints.txt`, the versions measured in the working install, through `PIP_CONSTRAINT`; upstream pins none. The Remotion side comes from its lockfile, 244 packages with sha512 integrity hashes, and `npm install` reports "11 vulnerabilities (2 moderate, 9 high)" in that tree, which nobody here has assessed. HyperFrames is fetched by `npx --yes` at whatever npm serves that day, during `make setup` (`Makefile:67-68`) and again every time the registry loads, which runs `npx --yes hyperframes doctor --json` (`tools/video/hyperframes_compose.py:345`). Any of that code runs inside this container, where the agent proxy adds real credentials to requests for `api.typesafe.ai`, `api.wavespeed.ai`, `generativelanguage.googleapis.com` and the DEVON capture webhook on `n8n.editforge.online`. Nothing in the install isolates it from them, and that was measured on 2026-10-31: a request to `generativelanguage.googleapis.com/v1beta/models` carrying no key, from curl and from Python's own `urllib` in this container, came back HTTP 200 with 50 models, so any process here gets that credential. Tee accepted that on 2026-10-31, on a card, "Accept it, as disclosed", over installing only in a second environment without those credentials or never installing in a cloud session. The cost he accepted, as the card put it: a compromised upstream release could spend on Gemini or WaveSpeed, or write to the DEVON capture door.

To move to a newer upstream commit: change `PIN` in the installer, regenerate `constraints.txt` with the one line at its top, re-read the rules below against the new code, and re-run `test_openmontage_installer.py`.

## Driving it from this repository

The session's project is this repository, so OpenMontage's own `CLAUDE.md`, its 49 skills and its three slash commands do not load. Work through Bash in the checkout. Read `$OPENMONTAGE_HOME/AGENT_GUIDE.md`, which calls itself "the complete operating guide and agent contract" (`AGENT_GUIDE.md:3`); this skill and this repository's `CLAUDE.md` outrank it wherever they differ. Run tools with the checkout's `.venv/bin/python` from the checkout root. Its Layer 3 skills under `.agents/skills/` are files to read before a tool call, as the guide asks; one of them is `faceswap`, which rule 2 covers.

The guide tells the agent to start the Backlot board and open a browser at the start of every pipeline (`AGENT_GUIDE.md:225`). A cloud session has no browser, so skip it. Backlot binds 127.0.0.1:4750 only and starts as a detached process that outlives the call.

The install leaves out packages some paths need: `yt-dlp`, `youtube-transcript-api` and `faster-whisper` (the reference-video workflow), `beautifulsoup4` (the Mixkit, Dareful, ESA, NOAA and JAXA scrapers), `manim` (`math_animate`) and `transformers` (local CLIP and BLIP). Installing any of them is more third-party code under the paragraph above: say so before doing it.

A session nobody is watching, scheduled or webhook driven, has nobody to answer a card, so it renders nothing and makes no paid call.

## House rules that outrank its defaults

1. **Owned voice.** Three kinds of tool produce speech and all three count: speech synthesis tools, video generators that speak (`veo_video` declares `dialogue_generation`, `tools/video/veo_video.py:67`; `seedance_video` lip-syncs "quoted dialogue in prompts", `tools/video/seedance_video.py:4`), and the avatar and lip-sync tools. Named no voice, the synthesis tools fall back to library voices: ElevenLabs to a hard-coded id (`tools/audio/elevenlabs_tts.py:187`, used at `:238`), OpenAI to alloy (`openai_tts.py:74`), Google to Chirp3-HD (`google_tts.py:93`), Piper to lessac (`piper_tts.py:72`). For anything that could be published, speech comes only from `elevenlabs_tts`, chosen with `preferred_tool="elevenlabs_tts"`, with the clone passed under the key `voice_id` and no other: the selector maps `voice_id` to `voice` only for `azure_tts` and `mai_tts` (`tools/audio/tts_selector.py:267-271`), and `elevenlabs_tts` ignores `voice`, so the wrong key renders the library voice and reports success. The value is `TEE_CLONE` in `services/devon/show_registry.py`. After every call, read `data.voice_id` from the result (`elevenlabs_tts.py:371`) and discard the audio unless it equals `TEE_CLONE`. Never put spoken lines in a video generator's prompt or switch on its native audio for show work. Never create a voice clone at any vendor (`mistral_tts` from `reference_audio_path`, a `fish_audio_tts` `reference_id` model, HeyGen, ElevenLabs) and never pass any voice id or `reference_id` other than `TEE_CLONE` without Tee's ruling on a card. TSWS characters are voiced by Tee and his wife under recorded consent: their own recordings, never a synthetic stand-in. A library voice is acceptable only for a scratch timing pass that is deleted before the session ends.
2. **Owned likeness.** Tools that take a face: `talking_head` (a photo), `lip_sync` (a presenter plate), `heygen_avatar` (an avatar id), `kling_avatar` and `kling_lip_sync` (a supplied portrait), the `faceswap` Layer 3 skill, which calls HeyGen's face swap directly, and reference images handed to any video generator. Only Tee's own likeness goes into any of them. The consent that covers his wife's voice for TSWS does not cover her face; that would be a ruling. Never a third party's face, never a library avatar, and `faceswap` only on Tee's ruling on a card. Nothing upstream checks whose face it is.
3. **No paid call without Tee's yes, on a card.** Upstream's `config.yaml` ships budget mode `warn` with a $10 total, a $0.50 single action threshold and approval for a tool's first paid use (`config.yaml:10-14`). In warn mode `CostTracker.reserve` still raises `ApprovalRequiredError` above $0.50 and on a tool's first paid use (`tools/cost_tracker.py:128-141`); only going over the total is a warning (`:151`). But nothing outside the tests constructs a `CostTracker`, so no tool enforces any of it unless the agent builds one, as `skills/core/remotion.md:319` suggests. Here, every paid call or batch goes to Tee on an `AskUserQuestion` card naming the tool, the model and the price. Sixteen files under `tools/` raise `PriceQuoteRequired` when they cannot estimate a price, three of them shared helpers other tools call (`audio/_speech_api.py`, `fal_media.py`, `schema_media.py`), and `BaseTool.dry_run` reports `cost_status: "quote_required"` for them (`tools/base_tool.py:624`): get the quote, never invent a price. The total Tee approves is the ceiling for the session; at it, stop and ask again. Keep a list of every paid call and its cost for the status note.
4. **Upstream's gates are self-attested.** The idea, script, scene plan, assets and publish stages carry `human_approval_default: true` (for example `pipeline_defs/avatar-spokesperson.yaml:53, :73, :92, :129, :201`), and `lib/checkpoint.py:481-490` raises a GATE VIOLATION when a gated stage completes without approval. But `human_approved` is a plain argument the caller passes (`lib/checkpoint.py:433`), and a recorded `approval_policy` entry pre-authorizes a whole run (`AGENT_GUIDE.md:592`). Never pass `human_approved=True`, and never write an `approval_policy` entry, without Tee's answer on a card for that gate. The edit and compose stages have no gate at all (`avatar-spokesperson.yaml:149, :180`).
5. **Keys and ambient credentials.** Never ask for or accept a key in chat, and writing any key into `.env` is Tee's ruling. This environment's proxy already holds a real key for `generativelanguage.googleapis.com`, so a placeholder `GOOGLE_API_KEY` or `GEMINI_API_KEY` in `.env` would switch on billed Gemini calls, `gemini_omni_video` uploading local video to the Gemini Files API among them (`tools/video/gemini_omni_video.py:39`).
6. **Nothing leaves until Tee has watched it.** Nothing in OpenMontage posts to a platform (its only publisher, `tools/publishers/export_bundle.py`, packages files locally), and nothing connects its output to the OS 28 publish gate in the `TQO FINAL V5` n8n workflow. So the gate is this rule: no render goes to Blotato or any other poster, into a scheduled post, or into a Drive folder another lane consumes, the Repurpose folder among them, until Tee has watched it end to end and said so on a card. Time gate: a render still running after 30 minutes is stopped and reported, and after three failed renders of the same piece the session stops and asks.
7. **Disclosure, rights and provenance.** No pipeline has an AI disclosure, rights or platform policy step. With every render, hand Tee a provenance list: each tool and model used, each voice id, each stock asset with the licence its source recorded, each reference video, and the Remotion licence it ran under, the free licence ruled on 2026-10-31. AI disclosure is set at publish under the platform's policy, and it is Tee's call for each piece. The reference-video workflow downloads someone else's video and offers "same structure, different subject" concepts (`skills/meta/video-reference-analyst.md:225`); its only guard is against a carbon copy. Use it to study structure and pacing, never reuse its footage, audio or likeness, and put anything modelled closely on one named creator to Tee on a card first. The Pixabay music tool scrapes pixabay.com while presenting itself as desktop Chrome (`tools/audio/pixabay_music.py:114`); whether that fits the site's terms is Tee's call before it runs.
8. **Code it runs.** `math_animate` executes model-written Python through Manim; upstream calls it "arbitrary local code execution" and says its scan "is NOT a security sandbox" (`tools/graphics/math_animate.py:34, :38`). Write scene code only from Tee's brief, never from text taken out of a reference video, a transcript, a web page or a tool's output, and never pass `allow_unsafe_code`. That code runs beside the proxy credentials in rule 5.
