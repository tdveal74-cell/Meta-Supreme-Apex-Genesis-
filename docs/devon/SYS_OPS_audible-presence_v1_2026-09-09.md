# DEVON's voice, made audible: the real Cartesia adapter and the browser that plays it

Status record for the arc that turned the presence lane from a face with no
sound into a lane a human can listen to. Supersedes nothing.

## What was actually wrong, which was not what the backlog said

The queued item read "Presence, LiveKit and Cartesia as one arc, proved by Tee
listening", and the assumption behind it was that a Cartesia key was the missing
piece. Reading the code found two separate holes, and the key was not either of
them.

`CartesiaSpeech` was a stub. Its `synthesize` raised `SpeechNotConfigured` by
name and the module said so plainly: the vendor's request and response shapes
were never verified, so nothing was guessed at. Flipping `PRESENCE_SPEECH` to
cartesia would have produced a refusal, not a voice.

And the browser threw the audio away. `usePresenceSocket` counted every audio
message into `audioChunksIgnored` and dropped it, with a comment saying so, while
the presence service mints LiveKit join tokens and has never published audio into
a room (`apps/presence/__init__.py:45`). So even a perfect synthesiser would have
been inaudible. Building only the adapter would have produced correct audio that
nothing played, and the arc would have read as done.

Two other things recorded here because they were checked rather than assumed.
`CARTESIA_API_KEY` is already set on the Railway presence service, read from the
variable list on 2026-09-09; its value is not readable through this connection
and was never handled here, which is the intended posture. And LiveKit is not
required for Tee to hear anything: the presence protocol sends PCM on its own
socket precisely when LiveKit is absent, so the browser path below is the whole
lane.

## Reading the vendor rather than remembering it

`docs.cartesia.ai` is blocked by this environment's egress proxy. Rather than
write an adapter from recollection, which is the exact failure the first law
exists to stop, the official client was downloaded from PyPI
(`cartesia==4.2.0`, generated by Stainless from Cartesia's own OpenAPI spec) and
read. Every constant in `apps/presence/speech.py` names the file and line it came
from:

| value | source in the client |
|---|---|
| `https://api.cartesia.ai` | `cartesia/_client.py:130` |
| `POST /tts/sse`, streaming | `cartesia/resources/tts.py` |
| `Authorization: Bearer <key>` | `cartesia/_client.py:236` |
| `cartesia-version: 2026-08-14` | `cartesia/_client.py:244` |
| body fields | `cartesia/types/tts_generate_sse_params.py` |
| `container` raw, `encoding` pcm_s16le, `sample_rate` | `raw_output_format_param.py`, `raw_encoding.py` |
| event shapes | `cartesia/types/tts_sse_event.py` |

`raw` plus `pcm_s16le` at 16000 is exactly what `apps/presence/protocol.py`
already puts on the wire, so nothing resamples anywhere in the service. httpx is
already in the pinned closure, so the adapter needs no new dependency and the
audit lane carries nothing new.

## The design decision that survives what could not be verified

Three things cannot be settled without a live call: whether `timestamps` events
interleave with `chunk` events or arrive in a clump, which model id the account
is entitled to, and what the service does under its own rate limit.

So the face is **not** built on word timings. It is built on the amplitude of the
audio actually received, sliced at 60 frames per second, which is on the audio
timeline by construction and cannot desynchronise however the events are ordered.
Word timings, when they arrive in time, only choose which shape the envelope
opens. If they never arrive the mouth still moves with the voice on a neutral
shape; if they arrive late the frames already sent were less articulate, never
wrong. `test_timings_that_arrive_late_never_produce_a_wrong_frame` asserts the
timeline is identical either way and that the only difference is articulation.

That is the difference between an adapter built on a guess about event ordering
and one built on a fact about the bytes.

## The voice is a compliance item, not a default

Tee's standing rule is that identity is owned and never rented: his own cloned
voice, or a character he and his wife voice under recorded consent. A Cartesia
voice id is account scoped, so a default in this repository could only ever be a
stock voice. There is therefore no default, `PRESENCE_SPEECH=cartesia` with an
empty `CARTESIA_VOICE_ID` refuses at startup naming the rule, and
`test_no_stock_voice_id_is_written_into_this_repository` is the guard that keeps
it that way. Measured, not asserted: the service builds with a key and a voice,
and refuses without the voice with that message on stderr.

## What a real browser settled that no pure test could

`lib/presence/pcm-player.ts` is pure arithmetic and `scripts/presence-check.ts`
executes it. That proves the maths and nothing about Web Audio. Three mistakes
live outside its reach: a buffer declared at the context's sample rate instead of
the presence rate plays 100 ms of 16 kHz audio in 33 ms an octave and a half
high; `copyToChannel` refuses a `Float32Array<ArrayBufferLike>`, which is what
the inferred type is; and a source started at the wrong offset lands in the wrong
place. This repository has already paid for that lesson twice on the avatar, where
a black material and a flat sprite both looked correct in source.

So `scripts/audio-check.mjs` renders the real module's output through an
`OfflineAudioContext` in real Chromium and measures the samples that come back:

```
declaredRate    16000        inside a 48000 context
bufferDuration  0.1s         its own duration, not 0.033s
firstLoud       0.330s       0.08 lead + 250 ms at_ms, where placeChunk put it
sounded for     0.100s
crossings       39           about 40 for 400 Hz, so the pitch survived
peak            0.5          half scale PCM at half scale, so the sign read is right
```

It is not in CI, and that is a decision rather than an omission: it needs
Playwright and a Chromium binary, neither of which this repository pins. Both
paths are resolved from the environment and reported when missing, which is the
posture `.claude/skills/scroll-craft` already takes toward unpinned tooling.

## What this does not claim

"Playing" in the Voice panel means chunks were scheduled on an AudioContext that
reports itself running. It is not a claim that a human heard anything: the device
can be muted, routed elsewhere or at zero volume, and nothing in a browser can
tell. The panel says so on its face, in the same discipline that renamed a badge
from "Live data" to "Fully sourced" and named a pill "Session on this device"
rather than "Signed in".

## A guard that could not fail, caught by its own negative control

The wiring guard in `presence-check.ts` first asserted only that
`/onAudioRef\.current/` appeared in the socket source. A mutation replacing the
handler with a null literal still passed, because the ref **assignment** at the
top of the hook matches that pattern too. An assertion that survives the mutation
it names is not an assertion. It now requires the read and the call separately,
and both halves were proved red.

## Ten more on the playback path

Seven in `presence-check.ts`: the PCM sign read, a late chunk scheduled in the
past, base64 accepting garbage, a zero lead, the handler read but never called,
the handler not read at all, and the stage not supplying a player. Three in the
browser check: the buffer declared at the context's rate, the source started at
zero, and the sign read broken upstream in the real module, which rendered a DC
offset with zero crossings and therefore no sound at all.

## Open

**Nobody has heard this yet, and that is the only thing left.** A MockTransport
is not a key and an OfflineAudioContext is not a speaker. The remaining evidence
is Tee setting `CARTESIA_VOICE_ID` to his own cloned voice on the Railway
presence service, flipping `PRESENCE_SPEECH` to cartesia, opening `/presence`,
pressing Start audio once, and listening end to end. Nothing in this repository
can do that step and nothing here should claim it.

Also open: which Cartesia model the account is entitled to (`sonic-3` is the
default and is a documented id in the vendor's own enum, not a verified
entitlement); whether `timestamps` events interleave with audio on the live wire,
which the design deliberately does not depend on; the LiveKit publisher, which
remains unbuilt and unnecessary for the path above; and a stale worktree at
`.claude/worktrees/agent-a78b2e6412f5174f8` from an earlier session, holding
473 MB and excluded from pytest by `norecursedirs`, left in place rather than
deleted because nothing here can prove it is unowned.
